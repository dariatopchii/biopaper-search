# BioPaper Search

Это первая рабочая версия проекта для твоего портфолио: поиск научных статей по биотехнологии и машинному обучению.

## Как открыть

В папке проекта запусти `Start-BioPaper.ps1` через PowerShell. Открой адрес, который появится в терминале: обычно http://127.0.0.1:8501.

## Что попробовать

1. Выбери вопрос о структуре белков или напиши свой запрос на английском.
2. Нажми Find papers. Первый запуск семантического поиска скачивает модели и строит индекс, поэтому он медленнее следующих.
3. Сравни результаты в трёх колонках. Keyword search ищет совпадения слов. Semantic search ищет смысловую близость. Semantic + reranking дополнительно оценивает пары «запрос — фрагмент статьи».
4. Открой исходные статьи. Проверь, отвечает ли аннотация на вопрос: высокая оценка модели ещё не означает полезность.

## Твоя следующая работа

Важно понять и доработать проект, чтобы уверенно обсуждать его на собеседовании.

- Прочитать реализацию поиска и уметь объяснить BM25, embeddings и reranking своими словами.
- Проверить предложенные исследовательские вопросы и сформулировать критерии релевантности.
- Создать набор кандидатов для разметки командой из README.
- В Relevance review оценить статьи: 0 — не подходит, 1 — частично полезна, 2 — прямо отвечает на вопрос. Название метода скрыто, чтобы уменьшить предвзятость.
- Начни с одного вопроса. Включён фильтр неоценённых статей: после Save and continue приложение показывает следующую. Оценка не выбирается заранее; если сомневаешься, оставь статью на потом.
- На странице Experiment results выбери Development. Когда все вопросы этого набора размечены и для каждого есть релевантные статьи, кнопка Run evaluation станет доступна. Она рассчитает метрики без терминала.
- Рассчитать метрики на development-наборе, изучить ошибки и только после выбора настроек проверить test-набор.
- Написать пять примеров ошибок и объяснить причины. Добавить настоящую таблицу результатов в README.

До ручной разметки проект показывает работающий поиск, но не доказывает улучшение качества. Не добавляй проценты улучшения в резюме до проведения эксперимента.

Test — отдельные отложенные вопросы. Используй их для финальной проверки после выбора настроек; не подбирай настройки по их результатам.

## Что можно развивать дальше

Сравнить общую модель с моделью для биомедицинских текстов, увеличить корпус, добавить оценку вторым человеком и сбор парных предпочтений. После этого можно исследовать обучение ранжирования по оценкам пользователей.
# Более глубокий эксперимент

В **Experiment results** добавлен **Run preference learning experiment**. Он обучает простую модель на предпочтениях, которые следуют из твоих оценок: 2 лучше 1, 1 лучше 0. Одинаковые оценки не создают предпочтения.

Первые 15 development-вопросов используются для обучения, следующие 5 — для проверки. Десять test-вопросов остаются для финального эксперимента. График покажет, как меняется качество при обучении на 2, 5, 10 и 15 вопросах. Пока ручных оценок недостаточно, запуск недоступен.

Если новая модель найдёт неоценённую статью, она добавится в **Relevance review**. Нужно оценить её и повторить запуск. Программа не подставляет оценку сама.

В **Project progress** видны цель, этапы, подтверждённый прогресс и следующий шаг. Те же документы лежат в `docs/`, чтобы история проекта была понятна на GitHub.
